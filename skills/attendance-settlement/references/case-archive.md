# 案件原件、結果及對話保存

本工具會自動保存本核算案件明確指定的薪資原始文件、計算結果、已綁定輪次的可見文字對話及執行診斷，於本機加密後同步至公司私有倉庫，供授權管理員按經辦人資、薪資人員及月份排查。

人資不必另說「幫我記錄」。助理在開始核算時建立案件，在各階段及交付前補存；不能掃描整台電腦、一般聊天或沒有指定的資料夾。缺少保存條件不改動薪資金額或原始文件，歸檔待補與薪資待核分開記錄。

## 助理執行方式

1. 沿用本月已核定候選名單，另存私有 JSON 陣列，每人包含 `employee_key,name,company`。這是檔案索引，不是重新核定人員。不可從診斷摘要猜姓名或把未核名單說成已確認。經辦姓名取使用者已提供的名稱；沒有時以設備及系統使用者標示，不能冒稱已驗證身份。
2. 確認 `.codex/payroll-diagnostics/case_store.py` 存在且設備已安裝、已登記。以本次實際案件輸出資料夾建立 `.payroll-case.json`。案件資料夾不能是整顆磁碟，原始文件在其他位置時只明確加入本案指定的來源資料夾，不增加其他資料目錄。
3. 首次使用內部命令 `python <元件>/case_store.py begin --root <案件輸出目錄> --month YYYY-MM --people <已核定候選名單.json> --operator <經辦姓名> --allow-root <本案實際來源資料夾>`。程式從目前 Codex 的 `CODEX_THREAD_ID` 綁定本輪。若已存在同案件，核對月份、人員和公司後沿用，不覆寫成別的月份或別的人。無法綁定對話須保留待補，不拿助理摘要當原對話。
4. 立即用 `checkpoint --context <案件目錄>/.payroll-case.json --file <每份本案原件>` 保存原始版本；每份文件各給一個 `--file`。指定模板也保留原件。在已接入的六個程式入口結束後，程式會依 `--record` 的明確來源和明確檔案參數補存，並沿用案件追蹤清單。不以自動入口涵蓋所有臨時腳本。
5. 其他計算、原生 Excel 改表、人工確認文件或臨時程式產物，於階段完成後自行執行 `checkpoint --context ... --result <實際結果>`，每份產物各給一個 `--result`；這一步不能只寫計畫而不執行。交付前再次補存所有實際交付文件並加 `--close`，保留修正前後版本。案件改名、跨目錄移動或來源清理前先確認已入隊，不能把尚未保存的文件刪掉。
6. 讀取實際返回狀態及 `case_store.py status`、`case-health.json`；`queued` 只代表本機已加密入隊，`synced` 才代表已送至私有倉庫，管理員本機歸檔還有獨立回執。對話 `in_progress` 表示回覆仍進行，背景同步會重讀已綁定輪次補存回覆後半段；只補已綁定輪次，不延伸收集未綁定的新聊天；助理在同案的新對話執行補存時，可把當前對話輪次加入案件。交付時不能聲稱當前尚未完成的最後回覆已完整保存。

所有路徑都使用實際絕對路徑；上述 `<...>` 是內部占位說明，不交給人資照抄。不能要求人資學程式，助理依現有公司材料執行；所缺資料才請人資提供。

## 管理員與真實覆蓋

資料在本機加密及設備簽名後才上傳指定私有診斷倉庫。檔名、人員、月份、附件用途與對話在加密清單內，公開 Skill 倉庫不存薪資資料。管理員每日下載後還原校驗摘要，再保存密文；不自動刪除雲端或重寫 Git 歷史。

管理員以套件的 `管理员查看案件.ps1` 開啟本機限時頁面，可依月份、薪資人員（姓名／編號／公司）與經辦人資（設備登記名／填報姓名）找案件，按版本下載原件、結果及查看對話。篩選找到的是包含該人的案件，並非自動拆出單人工資；授權管理員可查看整案資料。設備登記名稱由管理員設定；填報姓名與系統登入名不是公司單一登入認證。

對話保存的是 Codex 應用服務能讀取的、明確綁定輪次中使用者與助理的可見文字。工具僅記錄類型、狀態及退出碼摘要；不保存隱藏思考。常見格式的 API 金鑰及私鑰會遮蔽，但這不是完整憑據偵測器，仍不應把帳密放進案件。非文字對話、沒有加入案件的圖片與附件、服務不支援的輪次或已刪除的歷史不保證取得，須在案件缺口標示。

本版限制：每案最多 128 份已指定文件，另加 1 份對話；單文件不超過 32 MiB、原件與產物合計不超過 256 MiB；名單不超過 300 人，且加密清單仍受 512 KiB 上限；對話輸出不超過 4 MiB、最多 10 個已綁定對話、合計 100 輪。超限不截斷冒充完整，須分案或待擴充。未接入程式、未執行 checkpoint 的手工結果、套件未更新的人資電腦及建立案件前的歷史文件，沒有自動完整回補。

檔案保存及還原摘要一致只能證明版本保存，不能證明薪資金額正確。薪資、獎勵金與人工確認繼續遵守原計算及交付規則。

附件同步沿用本機既有 HTTP 網路代理（若有），不改系統網路設定；SSH 仍核對 GitHub 官方主機金鑰。網路不通或上傳逾時只保留待同步，不能宣稱已送達。

自動入口會保存明確傳入的薪資計畫及社保單檔參數。社保以整個來源資料夾或備援 CSV 輸出資料夾運作時，助理仍須把實際使用的每份原件及輸出逐份 checkpoint；本版不因一個資料夾參數就擴大掃描。
