# 三位人资部署与月度操作教程

## 1. 教程用途

本教程供艾美兰、范艳艳、俞霞共同执行公司月度工资核算。目标是让每位人资只需按阶段准备自己负责范围的资料，Codex 负责读取共享资料、核对人员范围、计算、生成异常清单并提示下一步。

不要在流程开始时一次性收集全部材料。完成一个阶段、人工确认一个阶段，再进入下一阶段。

## 2. 首次部署

### 在 Codex 中安装（Windows 与 macOS）

每台电脑首次使用时，打开 Codex 新对话，完整复制并发送：

```text
请从 https://github.com/sdasdasd1223/payroll-skill-suite 安装或更新四个工资核算 Skill。请先核对仓库与安装脚本，在 Windows 上使用 install.ps1，在 macOS 上使用 install.sh；如有旧版先备份。完成后核对四个 Skill 均已安装，告诉我备份位置和是否需要重启 Codex。不要修改 GitHub 仓库，不要把我的个人资料路径写入共用 Skill；这一步不开始算工资。若权限或安装失败，请给我具体错误。
```

人资不必亲自操作终端。若需要手动安装，Windows 可使用以下 PowerShell 命令；macOS 需下载完整仓库，在仓库根目录运行 `bash install.sh`。不能只下载单个脚本，因其需要同目录的 `skills/` 文件夹。

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force; $z=Join-Path $env:TEMP 'payroll-skill-suite.zip'; $d=Join-Path $env:TEMP 'payroll-skill-suite-online'; Invoke-WebRequest 'https://github.com/sdasdasd1223/payroll-skill-suite/archive/refs/heads/main.zip' -OutFile $z; if(Test-Path -LiteralPath $d){Remove-Item -LiteralPath $d -Recurse -Force}; Expand-Archive -LiteralPath $z -DestinationPath $d -Force; $i=Get-ChildItem -LiteralPath $d -Filter install.ps1 -Recurse | Select-Object -First 1; if(-not $i){throw '下载包中没有找到 install.ps1'}; & $i.FullName
```

看到“安装成功”后，完全退出并重新启动 Codex。以后更新也可以在 Codex 中重新发送同一请求；安装程序会先备份旧版本再安装最新版。

公开仓库地址：`https://github.com/sdasdasd1223/payroll-skill-suite`

GitHub 仓库和安装包保存三位人资共用的流程规则。每位人资电脑上安装的是各自的副本；告诉 Codex 本机资料地址，只会用于该人的核算，不会自动修改 GitHub 或其他人的 Skill。个人绝对路径、电脑用户名和员工资料不要写进 `SKILL.md` 或发布包。若要跨月记住常用位置，把资料总目录、正式模板、Offer 台账等实际地址记录在本机 Skill 安装目录之外的私有工作记录中；当月具体选用文件和确认结论记录在当月 `09-异常与确认` 或实际约定位置。重新安装会替换 Skill 目录，因此不要把这类个人记录只放在该目录内。换电脑、路径失效或有多个候选时，Codex 应重新向本人确认。只有有人主动修改、提交并发布共用规则，其他人更新安装后才会收到改动。

### 安装结果检查

安装完成后确认：

1. 确认 `payroll-operations`、`attendance-calculator`、`attendance-settlement`、`social-insurance-fund` 已出现在用户自己的 Codex Skills 目录；Windows 通常在 `C:\Users\<当前用户名>\.codex\skills\`，macOS 通常在 `~/.codex/skills/`；设置了 `CODEX_HOME` 时以该位置为准。
2. 确认每个 Skill 根目录都有 `SKILL.md`；`payroll-operations/agents/openai.yaml` 存在且界面文字为中文。
3. 确认飞书 CLI 已安装，并使用本公司有权读取花名册和通讯录的账号登录。
4. 重启 Codex，使新安装或更新的 skill 生效。
5. 第一次运行时说：`请使用 payroll-operations，开始 <工资月份> 的工资核算。资料在 <实际文件夹路径>，请先盘点文件，并按阶段告诉我缺什么。`

飞书登录、授权失效或实时读取失败时必须暂停。不要用上月缓存花名册代替实时花名册继续正式计算。

## 3. 每月目录

建议把同一个月的资料尽量集中在一个总文件夹，减少遗漏和版本混淆；下面是**推荐格式**，可放在桌面、共享盘或人资惯用位置，文件夹名不必一字不差。正式模板和跨月 Offer 台账可放在旁边的固定共享目录，不必每月复制。每位人资已有自己的资料夹时，也可以继续使用，首次只需告诉 Codex 各资料夹的实际位置。

```text
桌面\<YYYY-MM>-工资核算\
├─ 00-共享模板\（若正式模板不在长期固定目录）
│  ├─ 考勤表（模板）.xlsx
│  ├─ 五险一金汇总表（模板）.xlsx
│  ├─ 工资表（模板）.xlsx
│  ├─ 个税模板表.xls
│  └─ 飞书工资单模板表.xlsx
├─ 01-考勤原始数据\
│  ├─ 2026-09_每日统计_原始导出.xlsx
│  ├─ 2026-08_考勤汇总_人工确认版.xlsx
│  └─ 2026-09_加班数据_月末快照.xlsx（仅云端表不适合目标月份时提供）
├─ 02-考勤确认版\
│  ├─ 艾美兰\
│  ├─ 范艳艳\
│  └─ 俞霞\
├─ 03-五险一金\
│  ├─ 原始明细\（养老、失业、医保、公积金；按公司放置）
│  └─ 2026-09_全公司五险一金汇总_确认版.xlsx
├─ 04-工资资料\
│  ├─ 艾美兰\
│  │  └─ <公司或管理范围>\
│  ├─ 范艳艳\
│  │  └─ <公司或管理范围>\
│  └─ 俞霞\
│     └─ <公司或管理范围>\
├─ 05-新人Offer与调薪\
├─ 06-绩效与奖励\
├─ 07-人工调整\
├─ 08-输出\
└─ 09-异常与确认\
```

上面的 `2026-09` 只是文件名示例，使用时换成实际资料所属月份。文件名建议采用“`资料所属月份_负责人或公司_资料类型_状态.扩展名`”，例如 `2026-08_范艳艳_小竹工资底稿_人工确认版.xlsx`（供 9 月核算参考）、`2026-09_小竹考勤_人工确认版.xlsx`、`2026-09_未本养老_原始导出.xlsx`、`张三_Offer_2026-08-01.pdf`。原始平台导出文件可保留原名，另在同目录放一份简短说明，指出对应月份和公司；不要为了符合示例而修改源表内容。同一资料若有“初算、修正、确认”多个版本，文件名应明确状态，人工确认版不要与旧草稿混在一起而不标注。

现有文件夹不符合这个名称时**不必重新搬运或改名**。告诉 Codex 实际路径即可；Codex 要先检查文件内容并复述实际读取路径、月份、负责人／公司、资料类型、确认状态及选用理由。文件名看不懂、归属月份不明、同名文件多版、文件名与内容冲突时，Codex 列出候选和受影响事项，请人资确认后再使用。缺文件时先查已指定资料夹的同级和子目录，再具体询问，不要直接认定资料不存在。

首次使用时，另指出正式模板位置、当月 UserID 对照表位置，以及长期保存历史 Offer／新人薪资台账的位置。推荐把正式模板和历史 Offer 台账放在月度文件夹旁的固定共享目录，不写死某台电脑的用户名；Codex 在该人资自己的私有工作记录中记下实际位置，后续月份先核对路径及文件是否仍有效。若尚无台账，首次取得 Offer 时与人资确定存放位置并建立，原件只读归档。

### Codex 的首次资料盘点

先按使用者指定的位置查看文件，不要求人资预先按推荐目录整理。每份候选资料至少判断：实际路径、资料类型、所属月份或费用归属期、负责人／公司、原始／初算／人工确认状态，以及能否从表头和内容核实这些信息。把本阶段将使用的文件和未使用的同类候选简短列给人资，说明选用理由；只在存在缺失、冲突或无法辨认的地方提问，不让人资重新逐个介绍所有文件。

例如，发现 `9月工资-小竹.xlsx` 但表内标题是 8 月时，先问“这是 9 月核算所用的 8 月底稿，还是已有 9 月确认版在别处？”；同一目录出现两份“确认版”时，列出路径和差异，请人资指定版本。某份五险文件名写 10 月、实际费用属于 9 月时，以明细中的费用所属期和人资确认记录为依据。找不到 Offer、确认版考勤或人工调整时，说明受影响人员和字段；能独立计算的部分继续，受影响金额留空并列待核，不能套上月数据或默认值。

每次人资回答后，在当月 `09-异常与确认`（或实际约定位置）记录所选文件、确认人、日期、问题和结论。文件只是建议命名，不替代内容核对和人工确认；已确认的最终表在后续阶段优先于旧底稿。

## 4. 阶段一：考勤初算

### 人资要准备

- 工资月份。
- `01-考勤原始数据` 中的本月原始考勤。
- 上月最终确认的考勤汇总。
- 目标月份对应的加班数据。云端加班表混有后续月份、无法还原月末状态时，必须提供目标月份截止日的本地版本。

云端花名册、标准加班表和审批数据由 Codex 每月重新读取，不要求人资重复导出。需要登录或重新授权时，Codex 应停在授权步骤等待人工完成。

### Codex 要做

1. 说明读取的本地文件和云端来源。
2. 调用 `attendance-calculator`，核对入职、离职、迟到、缺卡、早退、请假、年假、育儿假、加班和累计结余。
3. 先解释差异或异常来源，再决定是否改数据；不得为了对齐历史结果直接修改。
4. 输出考勤初算表和异常清单到 `08-输出\考勤初算`，或使用者指定的输出目录。
5. 明确提示这不是工资结算版。

### 人工确认

人资将初算表发给员工确认，处理特殊情况后，把修正版分别放入 `02-考勤确认版\<负责人>`。人工修正后的版本是后续工资计算唯一考勤依据，不得被重新计算覆盖。

## 5. 阶段二：五险一金并表

### 人资要准备

- 各公司养老、失业、医保和公积金源文件，放入 `03-五险一金`。
- 本月是否纳入深圳广思。纳入时同时提供广思独立五险资料和公积金资料。

### Codex 要做

1. 调用 `social-insurance-fund` 合并多公司数据。
2. 保留原始明细和异常说明，不把缺失匹配静默填成 0。
3. 输出唯一一份共享的本月五险一金总表，不要求三位人资分别维护副本。
4. 提示用户先确认未匹配、同名、缺险种和广思资料是否完整。

确认后的总表建议放在 `03-五险一金\YYYY-MM_全公司五险一金汇总_确认版.xlsx`；人资实际放在其他地方时记录其真实路径。

## 6. 阶段三：三位人资工资资料

每位人资只维护 `04-工资资料\<本人姓名>` 下自己负责的公司或管理范围。

每个公司或范围建议包含：

- 上月或当月人资维护的工资底稿，用于读取人员历史薪资和人工字段。
- `02-考勤确认版` 中对应范围的确认版考勤。
- 本月新入职员工的 Offer 或录用通知，可放在该负责人资料夹或 `05-新人Offer与调薪`。
- 本月调薪、提前转正、岗位变动、特殊补贴等已确认资料。
- 本范围绩效、奖励金和其他人工调整资料；也可以统一放在 `06-绩效与奖励`、`07-人工调整`。

本月新人须用本人 Offer 或已确认薪资资料核实标准。历史月份已入职员工不要求每月重复提供 Offer；Codex 应先读取新人薪资条款台账和归档原件，再对照本人已确认工资记录及实时花名册延续薪资周期。历史 Offer 和台账都缺失或存在冲突时，列明缺项并询问人资，不自行补默认金额。

共享的正式工资模板放在使用者确认的模板目录：可以是月度总文件夹下的 `00-共享模板`，也可以是长期固定的 `薪资核算模板表` 等目录，只确定一处当前正式版。模板负责列、顺序、样式和公式，不负责提供人员名单、部门、组别或薪资金额。

## 7. 阶段四：新人薪资、绩效与奖励金预核

计算开始前，Codex 必须重新读取实时花名册，并先汇报：

- 三位人资各自识别到哪些公司或管理范围。
- 使用哪份确认版考勤、工资底稿、共享模板和五险一金总表。
- 哪些当月新人资料、绩效和人工调整已找到。
- 哪些资料缺失，是否需要暂停。

执行时遵守以下长期规则：

- 人员是否在发薪范围，以及所属公司、部门、小组，以实时花名册为准。
- 工资底稿是金额基础，不是最终人员名单；当月有工资的离职人员要保留，历史离职且本月无应发项目的人员要剔除，底稿缺少的应发薪新人要补入人员行。薪资资料缺失时金额留空并列异常。
- 现有员工在最新小组内保持原相对顺序；新员工放在所属小组末尾。
- 工资金额必须回查本人底稿、本人 offer 或本人已确认历史记录，不能根据另一名员工案例猜测。
- 六个月试用期且 Offer 写明试用和转正薪资的员工，按差额除以五逐月递增，周期从入职日开始；月初已生效的档位并入薪资，月中新增差额按生效计薪日折算。三个月试用期不逐月递增，转正工资待确认。
- 离职员工先核对离职日是否早于递增周期结束日；若是，该未完成周期的新增档位不生效，再按此前适用的已确认档位计算入离职差额。
- 绩效不是人人都有。确认无绩效可留空；尚未核算或资料未提供时也留空，但须标记待核，不能把缺资料当作已确认无绩效。奖励金按当月申报和核验资料预核。
- 有法定计薪节假日或跨月补班时，先从已确认的月度日历核准该员工适用的整月计薪天数，再按同一口径计算入离职差额；不得把不同标签分别机械减一天，重复扣减分母。2026 年 9 月，9 月 25 日是法定计薪节假日、不需要补班；9 月 20 日才是补 10 月的班。用户确认 9 月 18 日离职者的差额分母为 22 天，不再因 9 月 25 日另减一天；该员工未上 9 月 20 日补班，不涉及补班补偿。其他员工若实际上了 9 月 20 日补班、但 10 月已离职，应标注该出勤，由人资确认换一天调休或按日薪计入其他补贴。具体人员分母、日薪基数或跨节假日月中入职口径不明时，先询问用户。
- 普通在职非实习员工的事假时间默认不显示、不自动扣款，但所有人的请假扣款公式都保留，便于人资人工补录后联动。
- 实习生当月事假当月结算，分母为本月应出勤小时数；即使当月离职仍使用实习生口径。
- 非实习离职员工结算累计事假，分母为 174；累计值已经包含本月时不得重复相加。
- 请假扣款、考勤扣款、入离职差额等计算列保留公式，不写死。
- 产假按正常薪资与产假薪资分段；月中产假差额放在 `其他个人扣款`，不得放进入离职差额。复工后恢复正常薪资。
- 先按 Offer 和离职例外确定本月适用档位，再计算入离职差额；月中生效且符合在岗条件的当期补差放入其他补贴。该列已有人工金额时先保留并核对组成，请用户确认合并方式，不能覆盖或静默跳过补差。

## 8. 阶段五：工资计算和纠错

预核完成后才生成工资表。先按实时花名册确认人员身份和入离职日期，再结合工资底稿及当月已确认应发项目确定增删；离职所属月份仍结算，后续月份无补发则剔除。应发薪人员缺考勤时保留人员行并询问，不能沿用上月考勤或未经核实的工资金额。资料、人员、金额或结算方式有疑问时先请用户判断；用户要求待补版的，受影响金额留空并列异常。

人资可继续使用上月或更早月份的工资表作底稿。先识别底稿月份，并用本月实时花名册、历史花名册快照和已确认离职记录自动核对人员：本月离职仍结算；此前月份离职且无已确认本月应结项目者从新工资主表剔除，原底稿不改；状态或本月应结项目不明者集中询问人资，不直接沿用旧表金额。保留纳入、剔除、待核的差异及依据。

保留原底稿的批注、单元格注释和人工标注。计算列按正式模板保留可联动公式；`其他个人扣款`等人工列已有值时先保留，确认专项扣款是否已包含及如何合并，不覆盖也不重复计算。
- 数字写为真正的数字格式；0 按模板习惯显示为空白；负数不得出现两个减号。
- 不擅自增加模板没有的列，不改变字体、列宽、行高、边框、颜色或隐藏状态。
- 备注只保留必要的入离职时间和确需人工复核的事项，避免重复解释正常规则。

工资结果按负责人和公司范围输出到 `08-输出\工资表`，或使用者指定的输出目录；原始模板和底稿保持不变。

## 9. 阶段六：工资表人工确认

三位人资分别复核自己负责的工资表，重点检查：

- 人员、公司、部门和小组。
- 新人薪资、递增和补差。
- 实习生与离职员工事假。
- 病假、产假、入离职差额和个人扣款。
- 五险一金、绩效、奖励金和人工调整。
- 修改输入单元格后，公式是否自动更新。
- 字体、顺序、模板列和数字格式。

人资明确回复“工资表已确认”后，该版本成为本月正式工资基准。后续不得自行重算或回退。

## 10. 阶段七：个税表

### 需要的材料

- 已确认工资表。
- 使用者确认的正式模板目录中的政府个税原始模板。
- 实时花名册中的证件和所属公司信息。

### 输出规则

- 直接复制政府模板，不新建表格，不删除任何列。
- 个税人员来自已完成人员范围核定的本月工资表；旧月底稿或仍有人待核的初算表不能直接逐行导入。对不在实时花名册而拟进入个税表的人，先核实历史离职情况和本月应结依据；不清楚的集中询问人资。
- 只填写实际黄色列；`工号`是唯一经确认的非黄色例外，表头仍为`工号`，内容填写花名册所属公司。
- 黄色仅用于识别原模板的必填列；导出的个税表不保留任何单元格底色，其他格式和填表说明仍按原模板保留。
- 每位人资输出一份个税表。
- 缺证件、公司为空或匹配不唯一时写入异常，不猜测。

人工确认通过后，将个税表标记为本月正式版本。

## 11. 阶段八：飞书工资单

### 需要的材料

- 已确认工资表。
- 使用者确认的正式模板目录中的飞书工资单模板。
- 公司总账号的实时飞书通讯录授权。

### 输出规则

- 最终工资表中的当月有薪人员仍保留。
- 只有在公司总账号通讯录中匹配到唯一、已激活、非跨租户且**未离开组织**账号，并具备经核实手机号及实发金额的人进入飞书工资单。
- 对本月核定工资人员全体核查账号是否已离开组织，包括已经因缺手机号或金额被排除的人；查不到、未激活、跨租户、已离开组织或同名歧义人员排除。完整列出每人的全部已查明原因，查询失败则标待核，不能当作“未离开组织”。
- 不在工资单阶段重新计算工资金额。

## 12. 阶段九：最终交付

`08-输出`（或使用者指定的输出目录）最终应包含：

- 各负责人或各公司的最终工资表。
- 五险一金汇总表。
- 三位人资个税模板。
- 飞书工资单导入表。
- 飞书工资单排除与复核清单。
- 全流程异常清单。

Codex 最终必须汇报使用了哪些文件、各表人数、排除人数及原因、仍待确认的事项，并主动说明流程是否已经结束。

## 13. 每月启动话术

人资只需先说：

> 请使用 payroll-operations 开始核算 YYYY 年 MM 月工资。月度资料在“<实际文件夹路径>”，正式模板在“<实际模板路径>”。请先盘点现有文件，告诉我当前阶段缺什么，并一步一步提示我；名称或归属看不懂时直接问我。

Codex 应先检查考勤阶段的最小材料，不应立刻要求提供后续全部工资、个税和工资单资料。

## 14. 临时情况如何记录

以下内容放入 `09-异常与确认\当月运行说明.md` 或异常清单，不写进永久 skill：

- 某名员工当月特殊金额或人工处理结论。
- 某个月固定的应出勤小时数、人数或日期。
- 临时调组、跨公司、补发补扣和特殊发薪方式。
- 当月某份表缺列、错列或人工修订。
- 一次性排除人员及其原因。

只有人资明确确认“以后每个月都这样执行”的口径，才升级为通用规则并更新 skill。
